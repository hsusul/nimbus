# Onboarding

Nimbus has no first-run flow today. The safest near-term pattern is contextual guidance in authentic empty states, not a forced multi-step tour.

## Cloudy coverage model

- **Source platform:** Behance
- **Product/design:** Cloudy — Cloud File Storage Dashboard UI Kit
- **Direct URL:** https://www.behance.net/gallery/217245913/Cloudy-Cloud-File-Storage-Dashboard-UI-Kit
- **UI category:** Onboarding and connected product flows
- **Platform:** Web/responsive
- **What works well:** Onboarding is treated as one part of a larger system that includes search, restore/delete, notifications, and administration.
- **What should not be copied:** Its paid screens, assets, or an onboarding sequence for unsupported Nimbus features.
- **Reusable principle:** Onboarding should lead directly into real product value and disappear once the user is competent.
- **Nimbus application:** A first empty workspace can offer “Upload a file,” “Create a folder,” and a short explanation of direct-to-storage uploads; later sessions return directly to files.
- **Rights/status:** Paid commercial asset; not reused.
